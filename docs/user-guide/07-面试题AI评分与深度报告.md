# 面试题 AI 评分与深度报告

## 功能说明

面试题 AI 评分与深度报告是一套完整的智能评估体系，专门针对面试题和简答题提供 AI 驱动的自动评分、逐题反馈和深度分析报告。

核心能力包括：
- **自动评分**：提交答案后，系统自动逐题调用 AI 对面试题/简答题进行 0-100 分制评分，不阻塞页面操作
- **手动评分**：在答案速查视图中，对于未自动评分的题目可手动触发 AI 评分
- **评分反馈**：每道题展示分数、亮点、不足和改进建议，分数按区间着色
- **深度报告**：生成面试综合深度分析报告（消耗 100 积分），包含已掌握领域、薄弱领域和改进计划

适用题目类型：
- `interview`（面试题）
- `essay`（简答题）——系统会将其一并纳入评分范围

---

## 面试题的判定与识别

### 自动转换规则

当 AI 解析或手动创建题库时，系统会执行自动识别：

- 如果一道题库中的**所有题目**都是 `essay`（简答题）类型，系统会将它们**自动转换为 `interview`（面试题）类型**。
- 此规则在 AI 解析（`aiParseQuestions` 和 `aiParseQuestionsStream`）和题库创建/编辑（`POST /api/quizzes`、`PUT /api/admin/quizzes/[id]`）时均会生效。

### 答题界面中的面试题标识

在答题页面和答案速查视图中，面试题有以下视觉标识：

| 位置 | 标识方式 |
|------|----------|
| 题目卡片顶部标签 | 靛蓝色（indigo）背景标签，文字 **"面试题"** |
| 答题区域 | 多行文本输入框（与简答题相同），支持输入长文本回答 |
| 子问题 | 如果题目包含子问题（以 `- ` 开头），会以灰色小字列表形式展示在主问题下方 |
| 答案速查题型标签 | 靛蓝色（indigo）小标签，显示 **"面试"** |

## 自动 AI 评分（提交后）

### 触发时机

提交答案后，系统会立即启动自动评分流程：

1. 点击"提交答案"按钮，确认提交对话框后，系统提交答题结果到后台。
2. 页面跳转至**答案速查视图**（"答案速查"页面）。
3. 与此同时，`useEffect` 检测到 `submitted` 状态变更，自动开始逐题 AI 评分。

### 评分过程

自动评分采用**逐题串行、不阻塞页面**的策略：

| 阶段 | 表现 |
|------|------|
| 评分子集筛选 | 系统筛选出所有 `interview` 和 `essay` 类型且尚未有 `interviewScore` 的题目 |
| 评分开始 | 提交按钮变为禁用状态，显示旋转图标 + "AI 评分中..."文字 |
| 逐题评分 | 对每一道需评分的题目，调用 `POST /api/ai/grade-interview`，携带 `resultId` 和 `questionId` |
| 实时进度 | `autoGradeProgress` 状态跟踪 `{ done, total }`，即已完成/总需评分题数 |
| 结果更新 | 每题评分完成后，`result` 状态即时更新（`interviewScore` 和 `interviewFeedback` 写入对应题目） |

**提交按钮状态变化：**

| 阶段 | 按钮外观 | 状态 |
|------|----------|------|
| 正常状态 | 蓝绿渐变按钮，文字"提交答案" | 可点击 |
| 提交中 | 旋转图标 + 文字"AI 评分中..."（如果 `isSubmitting` 为 true） | 禁用 |
| 自动评分中 | 旋转图标 + 文字"AI 评分中..."（如果 `autoGrading` 为 true） | 禁用 |

### 失败处理

- 单题评分失败时，系统**静默跳过**该题，继续评分下一题（`catch` 块为空，不抛出错误）。
- 自动评分不会弹出错误提示，未成功评分的题目可在答案速查中手动重新触发评分。

## AI 评分标准（0-100 分制）

系统通过 `buildInterviewGradingPrompt` 构建评分 prompt，以**资深面试官**的角色对每道面试题/简答题进行打分。评分依据参考答案与学生的匹配程度。

### 分数区间说明

| 分数区间 | 含义 | 典型表现 |
|----------|------|----------|
| **90-100** | 回答全面、有深度、表达清晰 | 涵盖所有要点并有独到见解 |
| **75-89** | 回答较完整 | 涵盖大部分要点，表达较清晰 |
| **60-74** | 回答基本切题 | 但遗漏部分关键点或表达不够清晰 |
| **40-59** | 回答部分相关 | 但遗漏较多要点或表达混乱 |
| **20-39** | 回答勉强相关 | 几乎没有切中要点 |
| **0-19** | 回答完全无关或未作答 | 只有"不知道"、"不会"、空白、或完全无关 |

### 重要规则

> 如果学生的回答是 **"不知道"、"不会"、空白**、或与题目**完全无关**的内容，AI 将**直接判 0 分**。

### 评分输出结构

每道题的评分结果包含以下字段（`InterviewScoreResult`）：

```json
{
  "score": 85,
  "strengths": ["亮点1", "亮点2"],
  "weaknesses": ["不足1", "不足2"],
  "suggestion": "改进建议（50-150字）",
  "comment": "综合评语 Markdown 格式（80-200字）"
}
```

### 评分关注重点

| 题目类型 | AI 关注点 |
|----------|----------|
| 简答题（essay） | 要点覆盖、论述清晰度、补充建议 |
| 代码题（code） | 逻辑正确性、边界条件、代码风格 |
| 面试题（interview） | 是否切中要点、表达清晰度、是否有亮点 |

## 答案速查视图中的评分展示

进入答案速查视图后，找到面试题或简答题的条目，点击右侧箭头（`>`）展开详情。在展开区域中，**"AI 评分"** 部分分为两种状态：

### 已评分状态

当题目已有 `interviewScore` 时，展示以下内容：

**1. 分值展示**

- 大号粗体数字（`text-xl font-bold`），格式为 `{score}/100`
- 颜色按分数区间变化：

| 分数 | 颜色 |
|------|------|
| ≥ 80 | 翠绿色（`text-emerald-600`） |
| 60-79 | 琥珀色（`text-amber-600`） |
| < 60 | 红色（`text-red-500`） |

**2. 亮点列表**

- 绿色字体，以 ✅ 图标开头
- 每个亮点以中文分号 `；` 分隔，横向排列
- 标签文字："✅ 亮点："

**3. 不足列表**

- 黄色字体，以 ⚠️ 图标开头
- 每个不足点以中文分号 `；` 分隔，横向排列
- 标签文字："⚠️ 不足："

**4. 改进建议**

- 蓝色字体，以 💡 图标开头
- 以段落形式展示建议文字
- 标签文字："💡 建议："

**5. 评分区域背景**

- 整体区域为浅靛蓝渐变背景（`from-indigo-50 to-blue-50`）
- 靛蓝色边框（`border-indigo-200`）
- 白色圆角卡片

### 未评分状态

当题目还没有 AI 评分时，展示以下内容：

- **区域外观**：浅黄色背景（`bg-amber-50/50`），黄色虚线边框（`border-dashed border-amber-200`）
- **提示文字**："暂未评分"（黄色小字，居中）
- **操作按钮**：紫色（`bg-indigo-500`）圆角按钮，文字"**AI 评分**"，居中显示

## 手动触发评分

### 适用场景

以下情况下需要手动触发评分：

1. **自动评分未覆盖**：自动评分过程中某题因网络或其他原因跳过，未成功评分。
2. **查看历史记录**：通过历史切换器（HistorySwitcher）切换到旧答题记录时，旧记录可能没有评分数据。
3. **补评**：任何时候，只要题目尚未评分，都可以手动触发。

### 操作步骤

1. 进入答案速查视图（提交答案后自动进入，或通过首页题库列表进入）。
2. 找到需要评分的**面试题/简答题**条目。
3. 点击题目标题行展开详情（右侧箭头从 `>` 变为向下）。
4. 在展开区域找到 **"AI 评分"** 部分。
5. 如果显示的是"暂未评分"状态，点击右下方的紫色 **"AI 评分"** 按钮。
6. 按钮立即变为禁用状态，显示旋转动画图标 + "AI 评分中..."文字。
7. 等待 5~15 秒（取决于 AI 厂商响应速度）。
8. 评分完成后，区域自动切换为"已评分状态"，显示分数和反馈内容，**无需刷新页面**。

### 失败处理

- 如果评分失败，页面弹出 `alert` 对话框显示错误信息（如"AI 评分失败"或具体错误文字）。
- 点击确定关闭对话框，区域保持"未评分状态"，可再次点击按钮重试。

## 面试题 AI 深度报告

### 功能概述

面试题 AI 深度报告是一份**综合面试表现分析报告**，基于所有面试题/简答题的答题情况和 AI 逐题评分，由 AI 生成深度分析。

- **消耗积分**：**100 积分/次**
- **入口**：报告页面 `/result/[id]/report`

### 进入报告页面

有两种方式进入：

**方式一：从答案速查页进入**

1. 在答案速查视图中，顶部工具条右侧有一个绿色按钮 **"📊 查看报告"**。
2. 点击按钮，页面跳转至 `/result/[id]/report`。

**方式二：直接访问**

在浏览器地址栏中直接输入 `/result/[答题记录ID]/report`，或从首页题库列表中点击相关入口。

### 报告页面布局

进入报告页面后，页面从上到下依次显示：

| 区域 | 说明 |
|------|------|
| 顶部导航 | "← 返回"按钮，点击回到上一页 |
| 标题栏 | "📊 答题报告" + "📥 导出报告"按钮 |
| 总览面板 | 得分、正确率、对/错/未答统计 |
| 题型维度 | 柱状图展示按题型的正确率 |
| 难度维度 | 柱状图展示按难度的正确率 |
| AI 面试深度分析 | 面试题专区（详见下方） |

### 面试题判定

报告页面加载时会自动判定是否为面试题型：

- 判定条件：`questions` 中**所有题目**都是 `interview` 或 `essay` 类型。
- 判定为面试题型（`isInterview = true`）时，AI 分析区域切换为面试深度报告模式。

### 生成深度报告

**前提条件：**

- 当前答题记录中至少包含 1 道 `interview` 或 `essay` 类型的题目。
- 账户积分余额至少为 100 积分。
- 管理员已配置并激活至少一个 AI 厂商。

**操作步骤：**

1. 在报告页面找到 **"🤖 AI 面试深度分析（100 积分/次）"** 区域。
2. 如果尚未生成报告，该区域标题右侧显示一个**紫蓝渐变按钮**，文字 **"🔮 AI 面试分析"**。
3. 点击按钮，按钮变为禁用状态，显示"生成中..."文字。
4. 系统执行以下流程：
   - 检查积分余额（需要 100 积分）
   - 检查所有面试题/简答题是否已有评分，如缺少则**即时补评**（调用 `gradeOnTheFly`）
   - 补评结果会回写到数据库，下次不再需要补评
   - 汇总所有题目评分数据（每道题包含：分数、亮点、不足、建议、用户答案、参考答案）
   - 调用 AI 大模型生成综合报告
   - 扣除 100 积分并记录到积分流水
5. 等待 15~60 秒（取决于题目数量和 AI 响应速度）。
6. 报告生成完成后，区域显示报告内容。

### 报告内容详解

**1. 综合评分**

- 区域左侧显示**特大号数字**（`text-4xl font-bold`），为综合评分（0-100）。
- 颜色规则同单题评分：≥80 绿色、60-79 黄色、<60 红色。
- 下方灰色小字标注 " / 100 综合评分"。
- 区域右侧显示**整体评价**文字（Markdown 格式，200-300 字）。
- 整体区域为浅紫蓝渐变背景（`from-indigo-50 to-purple-50`），靛蓝色边框。

**2. 已掌握领域**

- 标题："✅ 已掌握领域"（翠绿色文字）
- 列表形式展示，每项一个浅绿色卡片（`bg-emerald-50`，`border-emerald-200`）：
  - 领域名称（深绿色加粗）
  - 具体表现描述（深绿色小字）
- 通常展示 2~4 个领域

**3. 薄弱领域**

- 标题："⚠️ 薄弱领域"（琥珀色文字）
- 列表形式展示，每项一个浅黄色卡片（`bg-amber-50`，`border-amber-200`）：
  - 领域名称（深琥珀色加粗）
  - 不足之处详细描述（深琥珀色小字）
  - 具体改进建议（蓝色小字，以 💡 开头，左侧有蓝色竖线装饰）
- 通常展示 3~6 个领域

**4. 改进计划**

- 标题："📋 改进计划"（蓝色文字）
- 淡蓝色背景卡片（`bg-blue-50`，`border-blue-200`）
- Markdown 格式的长文（400-600 字），包含四部分内容：
  - 薄弱点优先级排序
  - 每个薄弱点的具体提升方案（含推荐学习资源/练习方向）
  - 分阶段提升路径（短期/中期/长期）
  - 面试技巧建议

**5. 积分扣费提示**

- 报告底部灰色小字："本次扣 100 积分，剩余 {X} 积分"

### 积分不足处理

如果账户积分不足 100：

- "🔮 AI 面试分析"按钮点击后，不会生成报告。
- 在 AI 分析区域显示**红色错误提示框**（`text-rose-500`，`bg-rose-50`，`border-rose-200`）。
- 提示文字格式：`积分不足:需要 100,当前 {X}`
- 此时需前往积分页面充值后再试。

### AI 服务不可用处理

如果管理员未配置可用的 AI 厂商：

- 即时补评阶段会给每道题默认 0 分，不足提示为"AI 评分服务不可用，暂无法评分"。
- 报告生成过程中如果发现没有可用 AI 厂商，积分会被**自动回滚**（退还已扣的 100 积分），并显示错误。

## 导出报告

在报告页面顶部，点击 **"📥 导出报告"** 按钮，可将报告导出为 Markdown 文件下载。

导出文件命名格式：`{题库名称}_报告_{日期}.md`

导出内容包括：
- 总览（得分、正确率、对/错/未答统计）
- 按题型正确率
- 按难度正确率
- AI 面试深度分析（综合评分、整体评价、已掌握领域、薄弱领域、改进计划）

## 常见问题

### Q: 为什么有些面试题没有自动评分？

**原因可能有：**
1. 自动评分过程中该题的网络请求失败（系统静默跳过，不报错）。
2. 答题记录是历史旧数据（在自动评分功能上线前提交的）。
3. AI 厂商服务暂时不可用。

**解决方法：** 在答案速查视图中，展开对应题目，点击"AI 评分"按钮手动触发评分。

### Q: 简答题（essay）和面试题（interview）在评分上有什么区别？

- **评分标准相同**：两者都使用相同的 0-100 分制标准和 prompt。
- **题目展示相同**：在答案速查视图中，两种类型的题目都会显示 AI 评分区域。
- **自动转换**：如果题库所有题目都是 essay 类型，系统会自动转换为 interview 类型。
- **深度报告**：两者都会纳入面试深度报告的统计范围。

### Q: 深度报告生成失败会扣积分吗？

不会。系统设计了积分回滚机制：
1. 生成前先检查积分余额。
2. 扣积分和生成报告在同一个事务流程中。
3. 如果 AI 调用失败，已扣积分会通过 `increment` 操作回滚，同时记录一条 `reason: 'refund'` 的流水记录。

### Q: 深度报告可以重复生成吗？

每次点击"🔮 AI 面试分析"按钮都会**重新调用 AI 生成并重新扣除 100 积分**。面试题报告不做缓存，每次生成都是新的。

### Q: 评分结果中为什么没有 comment 字段显示？

`comment`（综合评语 80-200 字）字段会存储在数据库中，但当前前端界面展示的是 `strengths`、`weaknesses` 和 `suggestion` 三个维度的反馈。`comment` 主要用于后端记录和将来可能的扩展展示。

## 快速参考：相关 API 端点

| 接口 | 方法 | 用途 | 消耗 |
|------|------|------|------|
| `/api/ai/grade-interview` | POST | 对单道面试题/简答题进行 AI 打分（0-100），回写数据库 | 无积分消耗 |
| `/api/ai/interview-report` | POST | 生成面试题深度分析报告（含补评逻辑） | **100 积分/次** |

### 请求参数

**单题评分** `POST /api/ai/grade-interview`：

```json
{
  "resultId": "答题记录ID",
  "questionId": "题目ID"
}
```

**深度报告** `POST /api/ai/interview-report`：

```json
{
  "resultId": "答题记录ID"
}
```

### 评分响应

**单题评分响应：**

```json
{
  "interviewScore": 85,
  "interviewFeedback": {
    "strengths": ["亮点1", "亮点2"],
    "weaknesses": ["不足1"],
    "suggestion": "改进建议文字"
  }
}
```

**深度报告响应：**

```json
{
  "content": {
    "overallScore": 78,
    "overallComment": "整体评价Markdown文字...",
    "masteredAreas": [
      { "area": "领域名", "detail": "具体表现" }
    ],
    "weakAreas": [
```
